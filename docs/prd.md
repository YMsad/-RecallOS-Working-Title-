RecallOS PRD V0.1（纳瓦尔版）
一、产品定位
一句话：

一个帮你在阅读中“抵达理解瞬间”的学习工具。

不是：

笔记软件

Anki替代品

AI总结工具

ChatBot

是：

一个会追问你的学习伙伴

一个帮你“想通”而不是“记住”的系统

二、核心理念（基于纳瓦尔）
用户需要什么？
“想要的”：更快的速度、更少的努力、一键完成（短期爽）

“需要的”：真正理解、建立体系、能用自己的话讲给别人听（长期受益）

RecallOS选择做“需要的”。

什么是“理解的瞬间”？
用户在使用RecallOS时，突然说出这句话的那一刻：

“哦！原来这个和那个是连着的！”

这个瞬间就是RecallOS交付的核心价值。

三、目标用户
第一优先级：高中生/大学生

特征：每天要学大量内容，但效率极低

痛点：翻开书觉得懂了，合上书一片空白

深层痛点：“我花了时间，但我觉得什么都没留下”

第二优先级：终身学习者

特征：大量阅读，但读一本忘一本

痛点：书读完了，知识还是作者的

深层痛点：“我读了这么多，为什么还是不会用？”

四、核心体验（用户的完整旅程）
text
用户打开RecallOS
        ↓
选择一个想学的内容（粘贴一段文本/上传资料）
        ↓
【核心环节】AI开始追问
  → “这个概念的核心是什么？”
  → “为什么它重要？”
  → “如果没有它会怎样？”
  → “它和你之前学的X有什么联系？”
        ↓
用户回答（打字/语音）
  → 答对了 → AI追问更深一层
  → 答错了/不知道 → AI给提示，再试一次
  → 答偏了 → AI引导回到正轨
        ↓
AI总结今天的“理解瞬间”
  → “你今天真正搞懂了：XXX”
  → “它和你之前学的YYY是连接的”
  → “明天你可以继续深挖：ZZZ”
        ↓
用户离开时带走了一个“想通”的瞬间
关键设计原则：

每次学习不超过15分钟（防疲惫）

每次都留下一个“搞懂了”的感觉（正向反馈）

每次结束都预告明天内容（留存钩子）

五、MVP功能列表（极小版本）
P0（必须做）
功能	描述	目的
文本输入	用户粘贴一段想学的内容（或上传TXT）	最低门槛
核心追问	AI根据文本内容，生成3-5个层层递进的追问	引导用户思考，抵达理解瞬间
用户回答	用户输入回答，AI判断方向是否正确	主动参与，不是被动阅读
链接提醒	AI指出“这个概念和你之前学过的X有关”	建立知识连接
每日总结	学习结束时，AI生成3行总结	强化“搞懂了”的感觉
本地存储	所有数据存本地SQLite	用户拥有自己的知识资产
P1（可以不做）
功能	理由
PDF/EPUB解析	手动粘贴也能用，V0.2再加
知识图谱可视化	命令行/极简Web不需要
复杂复习调度	V0.1只做“理解”，不做“记忆”
注册/登录	本地版本不需要
移动端	先验证命令行/Web
六、最简单的验证方式
在V0.1发布后，用以下问题验证产品是否有效：

用户是否在某个时刻说出了“啊哈”？

用户是否能用自己的话复述今天学的内容？

用户明天是否主动回来（不需要提醒）？

如果以上三个答案都是“是”，产品成立。

七、成功指标（北星指标）
北星指标：每周“理解瞬间”完成次数

一个“理解瞬间” = 用户回答了AI的追问，并选择标记“我搞懂了”。

辅助指标：

次日留存率（目标 > 40%）

平均学习时长（目标 8-15分钟）

每周主动使用天数（目标 > 5天）

“我搞懂了”标记次数 / 追问次数（目标 > 60%）

八、明确不做什么（边界）
不做	原因
AI替用户总结	违背“逼用户思考”原则
多模态图片理解	技术成本高，MVP不需要
社交功能	不靠虚荣心驱动
游戏化（积分/徽章）	不靠外部激励驱动
云端同步	V0.1验证阶段不需要
花哨的UI	先验证核心体验，再美化
九、产品宣言
“你要的不是工具，是一个逼你‘想通’的人。”

RecallOS的目标：

不是做“更好的Anki”

不是做“AI版Notion”

是让每个学习者都拥有一个永不疲倦的苏格拉底

十、一句话总结
“把‘学习’从‘输入信息’变成‘输出思考’。”

这就是RecallOS要做的事。
