## 5. DeepSeek 客户端（core/client.py）

- 错误层级：`DeepSeekError` → `DeepSeekAuthError`(401/403) / `DeepSeekRateLimitError`(429) / `DeepSeekAPIError`(其他非 2xx) / `DeepSeekNetworkError`(超时/断连)。
- 重试策略：仅 `NetworkError/RateLimit/5xx` 重试，指数退避 + 抖动；最坏约 60s 内抛错。
- 用量：`chat_completion` 每次从响应 `usage` 写库 `usage_logs`，成本按 pricing 表估算（deepseek-chat/v4-flash 输入 ¥0.27 输出 ¥1.10 / 1M tokens；reasoner ¥2.00/¥8.00）。
- Key 解析 `_resolve_api_key`：配置了 Worker URL → `KeyManager.get_api_key()`，失败或 429 回退手动 Key。

## 6. V1.0 Key 分发架构

```
客户端 KeyManager                          Cloudflare Worker (get-key.js)
─────────────────                         ─────────────────────────
1. get_device_fingerprint()                校验 device 为 64 位 hex
   → SHA-256(用户名/MAC/磁盘序列 组合) ──→ 2. KV: global:revoked 撤销检查
                               GET /get-key?device=…
3. 读缓存 key_cache.json（24h 内有效则直接用）
4. 未缓存 → 请求 Worker                          3. KV: usage:{device}:{date} 每日计数
   （429 = DailyLimitExceeded → 回退手动 Key）     4. hash(device) % len(VALID_KEYS) 分配 Key
5. 写缓存 + usage.log                 ←── 返回 {apiKey, expiresIn:86400, dailyUsed}
```

- 接口：`/get-key?device=`、`/revoke?secret=`、`/unrevoke?secret=`、`/health`。
- 限额：每设备每日 20 次（KV 计数，TTL 24h）；全局撤销用 `global:revoked=1` 使一切 `/get-key` 返回 403。
- 真实 Key 值保存在**工作区外**（`~/.recallos/backup/`），仓库只留占位符；cached `key_cache.json` 头 16 位指纹落 usage.log。

## 7. 学习流程（core/session.py）

### 7.1 新流程状态机（V0.3.0，默认）

```
                begin()                      start_validation()
[未开始] ──────────────────→ [reading] ──────────────────────→ [validation]
  仅存 concept，无 AI                       AI 设计验证任务（type + difficulty 1–3）
                                                                  │AI 分析作答↓
                                        has_gap()=false           │has_gap()=true
                                        ┌───────────┘              ▼
                                        │                 [intervention] ──→ 缺口消失 / 连续2次无效
                                        │                        │         ──→ [complete]
                                        ▼                        ▼
                                        │       [relearn] ← 连续 3 次验证不过（回读重试）
                                        └────► [complete] + 入复习队列 ──► 自动总结(finish_auto)
```

- 关键常量：`MAX_LAYER=4`（旧流程层数）、`VALIDATION_MAX_ATTEMPTS=3`、`INEFFECTIVE_LIMIT=2`（连续无效干预上限）、`CONFIDENCE_PROMPT_RATE=0.3`。
- 会话持久化：`_persist_new_flow` 把阶段/验证/深化/LearnerState 全量写 `concepts` 同名列；`restore_session` 据此精确重建（含阅读答案、干预反馈、Learner State 快照）。
- 干预强度阶梯（`INTERVENTION_LADDER`）：hint → example → analogy → counterexample → question；`_next_intervention_level` 仅在更轻干预无效后升级。
- 回答丰富度分级（`_calculate_answer_richness`）：<30 字 → simple（生活类比）；>80 字且含例子 → rich（反事实）；否则 moderate（联系）——决定深化追问入口。

### 7.2 Learner State（core/learner_state.py）

```python
LEVEL_ORDER = ("surface", "relationship", "application", "essence")
```

- `LearnerState`：`understanding_level`、`understood[]`、`uncertain[]`、`misconceptions[]`、`last_response_quality(deep/partial/shallow)`、`next_best_action`、`learning_goal`、`intervention_history[]`。
- 演进规则：`update_from_analysis` 只升不降（never regress 已达最高层）；`has_gap()` = `uncertain or misconceptions` 非空；`should_stop()` = 无缺口且 `next_best_action == "none"`。
- 每次验证/干预回答都会更新它，并随会话 JSON 落库；恢复时从最近一次含 `understanding_level` 的快照重建。

### 7.3 Prompt 模板体系（core/prompts.py）

- 角色：`SYSTEM_PROMPT` 苏格拉底人设（不直接给答案、只给方向提示、一题一问、答错不惩罚等 8 条）。
- 旧四层：`_LAYER_GUIDES`（核心/重要/反事实/连接）+ 模式（零基础/有基础）+ 思维模型注入（黄金圈/场景化/类比/第一性原理）。
- 新流程：`validation_task_prompt`、`learner_state_analyzer_prompt`、`validation_feedback_prompt`、`intervention_decider_prompt`、`learner_state_updater_prompt`、`deepening_offer_prompt`、`deepening_question_prompt`。
- 深化顺序 `DEEPER_QUESTION_ORDER`：verification_plus → connection → counterfactual → action → first_principles。
- AI 输出全部经 Pydantic 校验：`CheckAnswerResult`、`SummaryResult`、`ConnectionSuggestion`、`TextTypeResult`、`ValidationTask(task,type,difficulty∈1–3)`、`LearnerStateAnalysis`、`Intervention(action,reason,content,requires_user_response)`、`LearnerStateUpdate`、`DeepeningOffer`。
- 结构化输出失败 → `SessionError`（可重试），不会崩页。

## 8. 复习调度（core/review.py）

```
间隔公式：next = min(7, 2**stage) 天   （stage 向下取整，1→2、2→4、3+→7）
通过：stage+1, count+1, mastery→搞懂了, 按公式推后
失败：stage=0, count+1, mastery→模糊, 明天再复习
单次 3 次全错（MAX_REVIEW_ATTEMPTS=3）：mastery→学习中, needs_relearn=True
```

- 每题以 `review_log` 留痕；首题优先取上一份总结的 `tomorrow_hook`，没有则 `review_question_prompt` 生成。
- 判题 `temperature=0` 保证确定性。

## 9. UI 层要点（app.py）

- 路由：`st.session_state.step` 分发 9 个页面；新流程开关 `RECALLOS_NEW_FLOW`（默认 1）。
- 提交链（规避 streamlit#7629）：`_run_pending`（按钮触发的 AI 待办）→ `_render_pre_answer_signals` → `_capture_chat_answer`（chat_input 回答）→ 按最新 stage 渲染，全程不 `st.rerun()`；复习页同款模式。
- 阅读：`_reading_paragraphs` 拆段、`_split_sentences` 拆句、`_extract_key_sentences` 抽关键句、`_bold_keywords` 关键词加粗。
- 历史：掌握度三组表格 + 行内展开/两步删除确认；`render_concept_detail` / `_render_history_inline_detail` 渲染详情。
- 用量：`get_usage_summary(since=…)` SQL 聚合 + `get_usage_trend` 近 7 天，`pd.DataFrame` 展示。

## 10. CLI 与桌面

- CLI（`cli/main.py`）：`python -m cli.main` 学习（旧四层流程），`--history` 历史回顾；`_ensure_api_key` 缺 Key 时交互输入并用 ping 校验。
- 桌面（`launcher.py`）：`_free_port` 挑空闲端口，`bootstrap.load_config_options` + `bootstrap.run` 启动 `app.py`；windowed 模式下 stdout/stderr 重定向 `~/.recallos/recallos.log`；数据目录自动落用户目录（见 4 节）。

## 11. 安全

- 仓库无真实 API Key/KV id/ADMIN_SECRET（见第 6 节占位符约定）。
- API Key 仅存本机 `~/.recallos/config.json`；Worker 返回的临时 Key 绑定设备指纹、24h 有效、每设备每日 20 次。
- 设备指纹：用户名 + 网卡 MAC + 磁盘序列等组合的 SHA-256（跨平台实现于 `device_fingerprint.py`）。
